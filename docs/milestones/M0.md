## Why

**A service registry (ADR-0014).** Adding a service normally means editing
Caddy, the tunnel config, Compose, env files and docs — five chances to forget
one, and the omission is silent. `services.yml` is now the only place a service
is declared; the rest is generated and its staleness is a commit failure.

**Wildcard DNS as a design constraint (ADR-0015).** `*.maxrommel.de` resolves
to Cloudflare, so a new service never needs a DNS record. Hostnames are derived
from `SERVICE_NAME + ENV + DOMAIN` at render time and never written literally
anywhere in the repository.

**ADRs before code.** The expensive question in two years is not *what* the
config says but *why*. Each ADR records the alternatives that were rejected and
the reason, including the points where the plan was revised: SOPS deferred to
M7, backups pinned to M5 with a throwaway-database rehearsal, dev/prod split by
prefix on one host rather than a second server.

**Ansible chosen for the host baseline (ADR-0001).** The host is the layer that
cannot be reconstructed from prose, and it is where a mistake locks you out.
Scope is capped at four roles; applications stay in Compose.

**`.env` before SOPS (ADR-0006).** SOPS solves distribution of secrets among
multiple parties. With one operator there is nothing to distribute. The second
party arrives at M7, and three rules — generated `.env`, committed
`env.example`, drift check — keep that migration cheap.

```bash
cd life-server

make check          # generated files current; .env complete
make ping           # server reachable over SSH
```

**A bug was found and fixed during verification.** The first `setup-env.sh`
generated no secrets and left `.env` world-readable: `head -c 40` closes the
pipe, `tr` dies on SIGPIPE, and `pipefail` aborted the script before `chmod`.
Caught because the checks above were actually run rather than assumed.

```bash

```

To remove the SSH key from the server as well:

```bash
ssh root@62.238.4.64 "sed -i '/life-server/d' /root/.ssh/authorized_keys"
```

Do this only with console access confirmed — it removes your key-based login.

## Common failure cases

**`make setup` fails on pyyaml or jinja2.** Externally-managed Python on macOS.
Use `python3 -m pip install --user --break-system-packages pyyaml jinja2`, or a
virtualenv.

**`make ping` fails with "Permission denied (publickey)".** The key is not
loaded. `ssh-add --apple-use-keychain ~/.ssh/life-server`.

**`make check` reports stale generated files.** Expected after editing
`services.yml`. Run `make generate` and commit the result.

**Pre-commit hooks do not run.** They need installing once:
`brew install pre-commit && pre-commit install`.

**`.env` reported as world-readable.** Re-run `./scripts/setup-env.sh` — it
re-applies `chmod 600`.

## Prerequisites for M1

**Required:**

1. `brew install ansible` — not currently installed
2. Root password stored in a password manager — this is the Hetzner Console
   (VNC) fallback, and it is what makes disabling root SSH safe (ADR-0013)

**Recommended:**

3. `brew install pre-commit shellcheck yamllint ansible-lint`
4. A Hetzner snapshot before M1 — optional, since the lockout rehearsal and
   console access already cover the lockout risk, but it turns any mistake into
   a two-minute rollback

**Decisions still open:**

- Backup target for M5: Hetzner Storage Box vs. S3-compatible. Not needed
  before M5.
- Cloudflare wildcard record `*.maxrommel.de` must be proxied (orange cloud)
  and pointing at the tunnel. Verified in M3, not needed before then.

## What M1 will do

1. hostname, timezone `Europe/Berlin`, 2 GB swap
2. create `deploy` user, install the SSH key, grant sudo
3. **lockout rehearsal** — a second session verifies `deploy` login and sudo
   *before* anything is disabled
4. only then: disable root SSH login and password authentication
5. UFW: `limit 22/tcp`, deny everything else inbound
6. fail2ban on sshd
7. unattended-upgrades tightened, automatic reboot at 04:00

All as Ansible roles. `make harden-check` shows the diff before `make harden`
applies it.
