# M13 — a fallback model router, so OpenClaw can think again

**Status:** built, **not deployed.** See "Why this is not deployed" below.
**Date:** 2026-08-24
**ADR:** [0021](../adr/0021-fallback-model-router.md)

## The problem

OpenClaw's agent turns return HTTP 400 from the subscription proxy. The message
the operator sees — "your API key has run out of credits" — is false; a minimal
request succeeded in the same minute.

Bisected on a captured request:

| tools | bytes | result |
|---|---|---|
| 2 | 25,910 | 200 |
| 3 | 26,380 | **400** |

Hermes tipped at 31,032 / 31,339 B through the same proxy in the same hour, so
the budget is counted in **tokens**, not bytes.

Ruled out by test: fewer tools, removing the skill catalogue (−5,013 B, still
400), all four models, and the native `/v1/messages` endpoint. The remaining
prompt is ~17.2 KB of identity, safety and behaviour with no large block left
to cut. The floor of a working OpenClaw is above the ceiling of this proxy.

## What was built

```
openclaw ──> omniroute ──tier 1──> cliproxy ──> Claude subscription
                       └─tier 2──> api.anthropic.com   (inert until keyed)
```

| File | What it is |
|---|---|
| `compose/omniroute/Dockerfile` | node:22-alpine + `npm i -g omniroute`, non-root, tini |
| `compose/omniroute/omniroute.json` | providers + tiered failover, declared in Git |
| `compose/omniroute/entrypoint.sh` | seeds config into the volume, same split as OpenClaw |
| `compose/omniroute/README.md` | the reasoning JSON cannot carry |
| `compose/docker-compose.prod.yml` | the service, the volume, OpenClaw repointed |
| `env.example` / `.env` | `OMNIROUTE_API_KEY`, `ANTHROPIC_API_KEY` |
| `docs/adr/0021-…` | why, and what it reverses |

Verified locally: Compose parses (14 services), `omniroute.json` is valid JSON,
`entrypoint.sh` passes `sh -n`, `make check` reports no new findings.

The dependency chain is `cliproxy → omniroute → openclaw`, each on
`condition: service_healthy`, so the router cannot take traffic before tier 1
is up — three early failures against a still-booting proxy would trip the
circuit breaker and park the subscription for no reason.

### Kept small on purpose

The operator's requirement was "the least memory that still gives everything
else". Dashboard (Next.js), vector memory (Qdrant), semantic cache and
telemetry are disabled; routing, tiered failover and circuit breaking are kept.
Limit set to 256M, which is a **ceiling, not a measurement** — an OOM kill on
first run means the trimming did not work, and that is better learned loudly.

### Deliberately not used

OmniRoute's headline feature is auto-fallback across 339 providers, 90+ free.
Tier 2 is a single direct Anthropic key instead. ADR-0018 rejected the
free-provider pool because these messages carry uni, work and job-application
context; that reasoning still holds and is why the pool stays unused. ADR-0021
reverses the *mechanism*, not the *reason*.

TLS-fingerprint stealth is switched off for the same class of reason: its
function is to defeat a counterparty's terms rather than work within them.

## Why this is not deployed

**No route to the server.** The operator's uplink went IPv6-only mid-session
(`2a01:599:…`, previously `165.1.187.194`); the Hetzner host is IPv4-only.
ICMP, port 22 and port 443 all time out together — not a service failure, no
network path at all. `curl -4 https://ifconfig.me` fails at name resolution
while the same URL answers over v6, which is what pins the cause.

This also explains erratic DNS during the session: hosts with an AAAA record
resolved, github.com did not.

## ⚠️ What is unverified, and must be checked on first deploy

The upstream repository could not be read — github.com is IPv4-only too.
**Everything about OmniRoute's configuration here derives from its own
marketing page.** Three specific risks:

1. **`OMNIROUTE_VERSION=1.0.0` is a guess.** If the tag does not exist the
   build fails loudly, which is the intended behaviour. Settle it with
   `npm view omniroute versions`.
2. **The `*_ENABLED=false` env names are unconfirmed.** An unrecognised env var
   is ignored *silently* — a dashboard that never got disabled will show up as
   an OOM kill, not as an error.
3. **The `omniroute.json` key names are unconfirmed** for the same reason.

## Deploy procedure

```sh
# 1. confirm the version exists, and correct the ARG if not
ssh deploy@<host-ip> 'npm view omniroute versions | tail -5'

# 2. sync + build + up
make deploy-stack

# 3. VERIFY BY MEASUREMENT, not by reading config back
ssh deploy@<host-ip> '
  cd /opt/life-server
  docker compose -f compose/docker-compose.prod.yml logs omniroute | head -40
  docker stats --no-stream prod-omniroute
  docker exec prod-omniroute wget -qO- http://127.0.0.1:20128/v1/models
  # this MUST fail — the dashboard is supposed to be off
  docker exec prod-omniroute wget -qO- http://127.0.0.1:20128/dashboard
'

# 4. the actual acceptance test: an agent turn that used to 400
ssh deploy@<host-ip> 'docker logs -f prod-openclaw'
# then send a WhatsApp message and watch for a reply
```

Rollback is one line — point `OPENAI_BASE_URL` for `openclaw` back at
`cliproxy:8317/v1` and redeploy. OpenClaw returns to today's broken-but-known
state; nothing else in the stack is touched.
